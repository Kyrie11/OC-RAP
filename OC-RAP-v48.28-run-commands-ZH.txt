六、RC=20 时并发运行全部 8 个消融
--------------------------------

# 每张 A30 同时运行四个约 1GB 的任务。限制每任务 CPU/数据线程，避免主机 I/O 竞争。
export ABLATION_ROOT=runs/ocrap_v48_28_provenance_margin_ablations_4828
mkdir -p "$ABLATION_ROOT"

ABLATION_ROOT="$ABLATION_ROOT" \
OCRAP_ROOT="$OCRAP_ROOT" \
SOURCE_RUN="$SOURCE_RUN" \
PROTOCOL_ROOT="$PROTOCOL_ROOT" \
CAL_SAFE="$CAL_SAFE" \
GPU0="$GPU0" GPU1="$GPU1" \
TASKS_PER_GPU=4 \
BATCH_SIZE=72 NUM_WORKERS=1 PREFETCH_FACTOR=2 \
FACTOR_EPOCHS=20 FACTOR_PATIENCE=6 \
ADMISSION_EPOCHS=18 ADMISSION_PATIENCE=6 \
EVIDENCE_ADAPT_LR=0.00015 \
OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  bash scripts/run_v48_28_parallel_ablations.sh \
  > "$ABLATION_ROOT/controller.log" 2>&1

cat "$ABLATION_ROOT/TASK_GPU_ASSIGNMENT.txt"
cat "$ABLATION_ROOT/ABLATIONS_STATUS.json"

四组：

A_three_factor_wide_range
  3 个 harm factors，scale=6。验证 hard-rule/harm-proxy 两个额外分量是否必要。

B_five_factor_old_range
  5 个 factors，scale=2。验证旧 harmful 表示上限是否导致 harm AUC=0.5。

C_five_factor_wide_range_regression
  5 个 factors，scale=6，regression-only。v48.28 主设计。

D_add_listwise_frontier
  C + safe-utility listwise/frontier。验证额外排序损失在 factor 修复后是否真正有益。

若 8 并发导致 CPU 或 TFRecord I/O 饱和，可将 TASKS_PER_GPU 调为 2，并分两次运行；不要通过增大 NUM_WORKERS 解决 I/O 争用。

七、结果判读顺序
----------------

1. factor_stage/model_v48_trac_sr/train_summary.json：best_epoch 必须 > 0。
2. FACTOR_TRANSFER_INTEGRITY.json：valid=true。
3. MODEL_INFERENCE_CONTRACT.json：component_count=5、component_scale=6、prior=-2、bounded=true。
4. Evidence harm AUC 是否脱离 0.5。
5. Near：Balanced v48.27 的 5 selected / 3 safe-positive / +0.251 advantage 是否扩大，同时 harmful 降低。
6. Contact：safe-positive AUC、correlation、top-1 regret、harmful switch 是否同步改善。
7. GATE_FAILURE_DECOMPOSITION.json：区分 development_rule_fit 与 certificate_generalization。
8. dev-shadow：确认物理指标有效，再分析 clearance/TTC/exposure、secondary contact/overlap/free-space/escape/stable stop。
9. 不得在 RC=20 时读取 held-out test/stress。
