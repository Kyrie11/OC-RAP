重要说明
--------

四个 wave：

A_engineering_contract_only
  只修 certificate JSON、训练/推理模型合同、exact split 和返回码；保留旧 checkpoint/safe-utility 选择方式。

B_add_safe_checkpoint_contract
  A + proposal-contained safe-positive checkpoint 定义、safe precision、invalid admission 和 safe top-1 regret。

C_add_execution_exact_safe_utility
  B + 与运行时完全相同的 sigmoid(admission)-0.5 safe-utility 训练尺度。

D_full_execution_physics_bridge
  完整 v48.26 主模型和物理诊断输出。

调度方式：
- 每个 wave：Balanced 独占 GPU0，Precision 独占 GPU1；
- 一张卡同时只运行一个任务；
- 每张 GPU 总计四个任务；
- 最大并发数为 2。

七、结果判读顺序
----------------

1. 工程合同
   - PIPELINE_FAILED.json 是否不存在；
   - MODEL_INFERENCE_CONTRACT.json 是否 pass；
   - certificate JSON 是否完整；
   - exact_split_ids=true；
   - gate_evaluated=true。

2. adaptation-dev checkpoint
   - direct_safe_positive_admission_recall_near/contact；
   - direct_safe_admission_precision_near/contact；
   - direct_invalid_admission_rate_near/contact；
   - direct_evidence_safe_top1_accuracy_near/contact；
   - direct_evidence_safe_top1_regret_near/contact。

3. certificate
   - certificate_data_valid；
   - frozen_rule_source.sha256；
   - source_rule_satisfied_dev_constraints；
   - proposal support；
   - verify selected count；
   - precision LCB；
   - harmful selected count/UCB；
   - positive recall；
   - macro concentration。

4. dev shadow Near 物理指标
   - collision/overlap 保持 0 或 paired non-inferior；
   - minimum/terminal clearance 与 TTC；
   - clearance/TTC deficit AUC；
   - near/critical exposure duration、episode count、longest run；
   - time-to-min 与 recovery gain；
   - DRS/PCD/NUP、干预率与干预 burst；
   - route progression、加速度、减速度、jerk、yaw-rate。

5. dev shadow Contact 物理指标
   - secondary/re-contact event、episode、scene rate；
   - overlap duration、episode count、longest run；
   - post-contact terminal clearance、gain、time-to-peak；
   - normalized free-space AUC、clearance deficit AUC；
   - sustained escape、time-to-escape；
   - stable-stop quality 与 time-to-stable-stop；
   - offroad、route progression、jerk、yaw-rate、干预率。

关键归因：

- A 即失败：仍有工程/模型合同问题，不做算法结论。
- B>A：旧 checkpoint 定义是主要瓶颈。
- C>B：训练/运行时 safe-utility 尺度错位是主要瓶颈。
- D>C 仅改善物理 shadow、不改善 gate：离线证书标签与闭环物理目标存在错位。
- adaptation-dev 好、certificate 差：泛化或有限样本支持不足。
- offline gate 指标好、shadow 不改善：PCD teacher 没有充分表达时间恢复过程；下一版本才应预注册 candidate-level physical auxiliary teacher。
- certificate 通过但 Safe paired/held-out stress 不达标：不能宣称投稿目标达到，应保留 gate 通过事实并修复物理策略。
