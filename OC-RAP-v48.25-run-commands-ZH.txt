========================================

重要说明
--------

1. 必须使用全新的 OUTPUTDIR，不得在 v48.24 输出目录中覆盖运行。

4. Held-out test/stress 只能在 RC=0 且脚本自动生成 NEXT_COMMANDS.txt 后运行。

四、RC=20 后查看结构支持与 learned gate
---------------------------------------

python - "$OUTPUTDIR" <<'PY'
import json,pathlib,sys
root=pathlib.Path(sys.argv[1])
for variant in ('balanced','precision'):
  for regime in ('near','contact'):
    p=root/'candidates'/variant/'calibration'/f'direct_value_risk_{regime}_v48.json'
    d=json.load(open(p))
    print('\n===',variant,regime,'===')
    print('certificate_mode:',d.get('certificate_mode'))
    print('threshold_source:',(d.get('frozen_rule_source') or {}).get('path'))
    print('valid_for_deployment:',d.get('valid_for_deployment'))
    print('rejection_kind:',d.get('rejection_kind'))
    print('oracle:',json.dumps(d.get('proposal_constrained_oracle_gate'),indent=2))
    print('verify:',json.dumps(d.get('verify'),indent=2))
    print('learned metrics:',{
      'benefit_auc':d.get('proposal_evidence_top1_positive_auc'),
      'safe_benefit_auc':d.get('proposal_evidence_top1_safe_positive_auc'),
      'harm_auc':d.get('proposal_evidence_top1_harm_auc'),
      'conditional_harm_auc':d.get('proposal_evidence_top1_conditional_harm_auc'),
      'correlation':d.get('proposal_evidence_top1_correlation'),
      'false_switch':d.get('proposal_evidence_nonpositive_false_switch_rate'),
      'harmful_switch':d.get('proposal_evidence_harmful_switch_rate'),
      'positive_regret':d.get('proposal_evidence_positive_top1_regret_mean'),
    })
PY

判读：

- rejection_kind=structural_support_infeasible：当前完整 certificate 的 proposal/标签/gate 合同仍不可行；不要重复训练 calibrator。
- oracle feasible=true 但 valid_for_deployment=false：结构可行，失败在模型表示、收益排序、风险前沿、admission 或 dev→certificate 泛化。
- verify num_selected=0：模型仍是 all-abstain 或 dev-frozen threshold 无法迁移。

九、结果判读顺序
----------------

1. 首先确认 pipeline_valid、gate_evaluated、certificate_data_valid 和 test_roots_read。
2. 确认 validation teacher index 来自 evidence_adapt_dev，而不是 train index。
3. 检查 best checkpoint 的 hard admission rate 与 positive admission recall，不只看 soft mass。
4. 检查完整 certificate proposal-constrained oracle。
5. 检查 learned benefit/safe-benefit/harm/conditional-harm AUC、correlation、regret、false/harmful switch。
6. 检查 verify frontier 和最终 selections。
7. 最后看 adaptation-dev shadow 的物理 paired 指标。

关键归因：

- A 比 v48.24 明显改善：silent wiring bug 是主要原因。
- B>A：all-abstain checkpoint barrier 有效。
- C>B：bounded admission ceiling 是主要阻塞。
- D>C：连续 ranking/frontier 产生额外协同收益。
- 离线改善、shadow 不改善：teacher/feature 与物理闭环错位。
- shadow 改善、certificate RC=20：dev→certificate 泛化或 finite-sample power 问题。
- full certificate oracle fail：标签/macro/gate 支持合同仍有结构问题。
