四、RC=20 后先查看 proposal-constrained oracle audit
----------------------------------------------------

python - "$OUTPUTDIR" <<'PY'
import json, pathlib, sys
root=pathlib.Path(sys.argv[1])
for variant in ('balanced','precision'):
    for regime in ('near','contact'):
        p=root/'candidates'/variant/'calibration'/f'direct_value_risk_{regime}_v48.json'
        d=json.load(open(p))
        print('\n',variant,regime)
        print(json.dumps(d.get('proposal_constrained_oracle_gate'),indent=2))
PY

解释：

1. Oracle fit/verify 均可行，但 learned gate failed：
   冻结 proposal 内存在足够安全机会，问题属于表示、连续收益排序、
   high-benefit harm frontier 或 admission calibration。

2. Oracle audit 失败：
   当前冻结 top-k、标签定义和 gate 支持的组合本身不能通过。
   不要再重复训练 calibrator，也不要在当前输出目录调低 gate。
   需要在后续新版本中重新预注册 proposal/标签/证书协议。

注意：oracle audit 忽略 macro concentration，因此它是必要条件，不是最终 pass。

七、结果判读顺序
----------------

1. 先看 proposal_constrained_oracle_gate。
2. 再看 candidate 与 learned top-k：
   - benefit/safe-positive AUC；
   - score-teacher correlation；
   - positive top-1 regret；
   - high-opportunity conditional harm AUC；
   - learned harmful/false switch。
3. 再看 fit nearest frontier，而不是只看最终 coverage=0：
   - empirical precision 与 precision LCB；
   - harmful selected count/UCB；
   - positive recall；
   - macro concentration。
4. 查看 dev shadow 的物理 paired 指标：
   Near：minimum clearance、minimum TTC、危险暴露时长、deficit AUC、DRS/PCD/NUP、干预率。
   Contact：secondary contact、overlap duration/run、post-contact free-space AUC、
            sustained escape、time-to-escape、stable stop、DRS/PCD/NUP、干预率。

关键归因：

- B>A：连续 benefit ranking 有效。
- C>A：high-benefit safety-frontier 监督有效。
- D 同时优于 B/C：两者兼容，可作为论文主模块。
- Oracle pass + 离线改善 + dev shadow 不改善：offline teacher/feature 与物理闭环错位。
- Oracle pass + dev shadow明显改善 + gate failed：finite-sample gate 可能过于保守；
  记录结果，在新版本中预注册新的证书协议或增加 certificate 支持，不能事后改当前 gate。
- Oracle fail：proposal/label/gate 合同有问题，不再重复 calibrator 实验。
