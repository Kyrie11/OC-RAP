OC-RAP v48.34 BARRIER-CROSSFIT
主实验、消融、探索性闭环、外部baseline与critical视频执行指令

总原则
======
1. 先只运行v48.34主实验。不要预先运行消融、shadow、正式test或stress。
2. 不修改GATE_SPEC，不手工创建NEXT_COMMANDS.txt，不把RC=30当作算法结果。
3. v48.34继续使用统一top-5、一个模型和统一连续物理余量；没有regime ID或三套策略。
4. RC=20后的closed-loop/baseline/video是“探索性诊断”。它不会授权部署或论文主结论。
5. 若在RC=20后主动查看held-out test，必须承认这些场景已被后续模型选择污染，不能再用于v48.35及之后的调参、checkpoint或threshold选择。

三、严格按RC分支
===============

A. RC=30
-------
含义：工程、协议、数据合同、缓存、训练、模型合同或certificate artifact失败。
立即停止。不要运行消融、shadow、探索性baseline、video、test或stress。

收集：

find "$OUTPUTDIR" -maxdepth 4 -type f \
  \( -name 'PIPELINE_FAILED.json' \
  -o -name 'VARIANT_STAGE_FAILED.json' \
  -o -name 'FAILURE_SIGNATURE_*.json' \
  -o -name 'TRAINING_CONTRACT.json' \
  -o -name 'FACTOR_CACHE_*.json' \
  -o -name 'METRIC_CALIBRATION_CONTRACT.json' \
  -o -name 'CALIBRATION_FAILED.json' \
  -o -name 'V48_34_COMPLETE.json' \) -print

tail -n 200 "$OUTPUTDIR/logs/adapt_balanced.log" 2>/dev/null || true
tail -n 200 "$OUTPUTDIR/logs/adapt_precision.log" 2>/dev/null || true
tail -n 240 "$OUTPUTDIR/logs/certificate_controller.log" 2>/dev/null || true

六、视频选择与解释
================
工具会从全部已配对场景中同时选择：
- positive examples：相对Control在注册连续指标上有改善，且不引入明显安全退化；
- failure examples：干预导致NUP、安全或恢复指标恶化；
并生成Control/OC-RAP并排MP4和GIF。

不要只展示positive video。论文toy example或补充材料中必须同步披露选择规则、总场景数、positive/failure数量以及对应aggregate paired结果。
