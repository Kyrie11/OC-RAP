OC-RAP v48.35 CONTINUOUS-FRONTIER 下一步执行指令
=================================================

原则
----
1. 主实验只读取 train/evidence_adapt_dev/certificate_pool，不读取 test。
2. Near/Contact 只作为证书审计分层；模型不输入 regime ID，且只拟合一份共享 rule。
3. RC=0 才会生成 NEXT_COMMANDS.txt，并授权 Safe paired non-inferiority 与 held-out stress。

5. RC=30 是工程/协议错误；该次结果不得用于算法归因。

------------

B. RC=20
~~~~~~~~
不要读取test。先汇总：

python tools/summarize_v48_34_gate_failure.py \
  --run "$OUTPUTDIR" \
  --output "$OUTPUTDIR/GATE_FAILURE_DECOMPOSITION.json"

重点检查：
  1. candidates/*/calibration/dev_frozen_shared_rule_v48.json
  2. shared rule 的 by_stratum constraint_failures/constraint_deficit
  3. direct_value_risk_near_v48.json 与 direct_value_risk_contact_v48.json
  4. proposal_deployed_rule_* 指标（不要再使用旧字段名做新归因）
  5. CONTINUOUS_FRONTIER_CONTRACT.json、MODEL_INFERENCE_CONTRACT.json、TRAINING_CONTRACT.json

随后执行下面的2x2消融，不读取test：

MAIN_RUN="$OUTPUTDIR" \
ABLATION_ROOT=runs/ocrap_v48_35_continuous_frontier_ablations_4835 \
SOURCE_RUN="$SOURCE_RUN" OCRAP_ROOT="$OCRAP_ROOT" PROTOCOL_ROOT="$PROTOCOL_ROOT" \
GPU0=0 GPU1=1 \
bash scripts/run_v48_35_continuous_frontier_ablations.sh

消融解释：
  A legacy relative + safety_slack
  B physical_relative + safety_slack
  C legacy relative + frontier_capped_slack
  D physical_relative + frontier_capped_slack（主实验）

只比较 pipeline_exit_code 为0或20且 pipeline_valid=true、gate_evaluated=true 的任务。
任何RC=30任务不进入算法表。

~~~~~~~~
不要做算法结论。依次查看：

  $OUTPUTDIR/V48_35_COMPLETE.json
  $OUTPUTDIR/FAILURE_SIGNATURE_balanced.json
  $OUTPUTDIR/FAILURE_SIGNATURE_precision.json

优先排查：数据/scene role、checkpoint SHA、factor cache、共享rule SHA、脚本依赖、CUDA/OOM、空proposal rows。
修复工程问题后使用新的OUTPUTDIR重跑，避免继承陈旧状态文件。

五、论文主表准入条件
------------------
Near和Contact同时满足以下条件前，不进入CCF-A主结论：
1. 同一共享rule在adaptation-dev满足注册约束；
2. scene-disjoint certificate上RC=0；
3. Safe paired non-inferiority通过；
4. 同scene-ID、同target、同rollout horizon的paired closed-loop显示稳定收益；
5. 报告所有失败例，不只挑正向视频；
6. 多seed/置信区间支持结论。
