OC-RAP v48.20 UNISON-BRIDGE 下一步执行指令
===============================================

原则
----
1. 使用新的输出目录，不要覆盖 v48.19。
2. 主实验 Balanced 与 Precision 分别独占 GPU0/GPU1。
3. 只有 RC=0 且自动生成 NEXT_COMMANDS.txt 后才能运行 stress/test。
4. RC=20 只运行新的 v48.20 消融，不改 gate、不读 test。
5. RC=30 只排查工程阶段；不要把它解释为算法失败。

一、环境与代码完整性检查
------------------------

cd /path/to/OC-RAP-v48.20-UNISON-BRIDGE
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"

python -m compileall -q src tests tools
pytest -q
find scripts -type f -name '*.sh' -print0 | xargs -0 -n1 bash -n

确认以下源 checkpoint 均存在：

ls -lh runs/ocrap_v48_13_terra_proxy_4801/candidates/balanced/model_v48_trac_sr/best.pt
ls -lh runs/ocrap_v48_13_terra_proxy_4801/candidates/precision/model_v48_trac_sr/best.pt

二、v48.20 主实验：两张 A30 各运行一个 variant
---------------------------------------------

cd /path/to/OC-RAP-v48.20-UNISON-BRIDGE
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"

OUT=runs/ocrap_v48_20_unison_dedicated_4820
mkdir -p "$OUT/logs"

set +e
OUTPUTDIR="$OUT" \
OCRAP_ROOT=/data0/senzeyu2/dataset/OCRAP \
SOURCE_RUN=runs/ocrap_v48_13_terra_proxy_4801 \
PROTOCOL_ROOT=/data0/senzeyu2/dataset/OCRAP/calibration_v48_14_prism_4814 \
CAL_SAFE=/data0/senzeyu2/dataset/OCRAP/calibration_safe \
GPU0=0 GPU1=1 \
NUM_WORKERS=3 PREFETCH_FACTOR=2 BATCH_SIZE=72 \
EVIDENCE_ADAPT_EPOCHS=24 EVIDENCE_ADAPT_PATIENCE=7 EVIDENCE_ADAPT_LR=0.00025 \

bash scripts/run_v48_20_unison_dedicated.sh \
  > "$OUT/controller.log" 2>&1
RC=$?
set -e

echo "v48.20 main RC=$RC"
cat "$OUT/V48_20_COMPLETE.json"
[[ ! -f "$OUT/PIPELINE_FAILED.json" ]] || cat "$OUT/PIPELINE_FAILED.json"
[[ ! -f "$OUT/learning_gates_v48_20.json" ]] || cat "$OUT/learning_gates_v48_20.json"

返回码解释：

RC=0  ：Natural gate 有效通过，NEXT_COMMANDS.txt 应自动生成。
RC=20 ：协议、训练和 certificate 有效，但算法未通过；执行第四节新消融。
RC=30 ：工程/协议/数据/index/checkpoint/certificate 工件失败；执行第三节排错。

四、RC=20：运行 v48.20 非重复消融
--------------------------------

四组：
A_candidate_tail_only
B_safe_set_aggregate_harm
C_component_safe_set_no_balance
D_full_unison

执行方式：Balanced 一波四任务并发，Precision 一波四任务并发；每波 GPU0 两任务、GPU1 两任务。脚本默认每任务 NUM_WORKERS=1，以限制 CPU 和磁盘争抢。

cd /path/to/OC-RAP-v48.20-UNISON-BRIDGE
export PYTHONPATH="$PWD/src${PYTHONPATH:+:$PYTHONPATH}"

ABL=runs/ocrap_v48_20_unison_ablations
mkdir -p "$ABL/logs"

set +e
ABLATION_ROOT="$ABL" \
OCRAP_ROOT=/data0/senzeyu2/dataset/OCRAP \
SOURCE_RUN=runs/ocrap_v48_13_terra_proxy_4801 \
PROTOCOL_ROOT=/data0/senzeyu2/dataset/OCRAP/calibration_v48_14_prism_4814 \
CAL_SAFE=/data0/senzeyu2/dataset/OCRAP/calibration_safe \
GPU0=0 GPU1=1 \
NUM_WORKERS=1 PREFETCH_FACTOR=2 BATCH_SIZE=64 \
EVIDENCE_ADAPT_EPOCHS=24 EVIDENCE_ADAPT_PATIENCE=7 EVIDENCE_ADAPT_LR=0.00025 \
REBUILD_ADAPT_INDEX=1 \
bash scripts/run_v48_20_parallel_ablations.sh \
  > "$ABL/controller.log" 2>&1
ABL_RC=$?
set -e

echo "v48.20 ablation RC=$ABL_RC"
cat "$ABL/ABLATIONS_STATUS.json"
[[ ! -f "$ABL/ABLATIONS_FAILED.json" ]] || cat "$ABL/ABLATIONS_FAILED.json"
[[ ! -f "$ABL/ablation_summary_v48_20.json" ]] || cat "$ABL/ablation_summary_v48_20.json"

消融判读：
- B 明显优于 A：deployment-exact safe-set 组级目标是关键。
- D 明显优于 B：component heads 提供独立增益。
- D 明显优于 C：global auxiliary balance 有增益，但仍只是辅助项。
- C≈D 且均优于 B：balance 可删除，保留 component safe-set。
- A/B/C/D 全部 RC=20：优先检查 top-k safe-positive 支持、Contact component-head 校准和 fit→verify macro 集中，不再重复阈值调参或 regime residual。
