============================================================
1. 推荐：复用v48.34已经完成的两个checkpoint，从合同检查处继续
============================================================

# 必须指向服务器上原始v48.34运行目录的绝对路径。
export OUTPUTDIR=/ABSOLUTE/PATH/TO/runs/ocrap_v48_34_barrier_crossfit_dedicated_4834

# 两个checkpoint必须仍在服务器；上传到聊天的结果包为了体积没有包含它们。
test -f "$OUTPUTDIR/candidates/balanced/model_v48_trac_sr/best.pt"
test -f "$OUTPUTDIR/candidates/precision/model_v48_trac_sr/best.pt"
test -f "$OUTPUTDIR/V48_34_COMPLETE.json"
test -f "$OUTPUTDIR/PIPELINE_FAILED.json"

set +e
bash scripts/repair_v48_34_rc30_model_contract_with_v48_34_1.sh \
  2>&1 | tee "$OUTPUTDIR/v48_34_1_repair_controller.log"
RC=${PIPESTATUS[0]}
set -e

echo "V48.34.1 pipeline RC=$RC"
cat "$OUTPUTDIR/V48_34_1_COMPLETE.json"
cat "$OUTPUTDIR/RC30_REPAIR_PROVENANCE.json"

case "$RC" in
  0)
    echo "RC=0：检查NEXT_COMMANDS.txt；正式后续只执行该文件中的命令。"
    test -s "$OUTPUTDIR/NEXT_COMMANDS.txt"
    ;;
  20)
    echo "RC=20：pipeline和certificate有效。停止在这里，把完整OUTPUTDIR打包后进行下一轮算法分析。"
    test -s "$OUTPUTDIR/NEXT_COMMANDS_BLOCKED.json"
    ;;
  30)
    echo "RC=30：仍是工程/协议失败。不要运行消融、shadow、test、stress、baseline或视频。"
    exit 30
    ;;
  *)
    echo "未知RC=$RC，按工程失败处理。"
    exit 30
    ;;
esac

# 建议打包（保留JSON/CSV/log，checkpoint可按服务器传输条件决定是否排除）
cd "$(dirname "$OUTPUTDIR")"
zip -qr "$(basename "$OUTPUTDIR")_v48341_results.zip" "$(basename "$OUTPUTDIR")" \
  -x '*/checkpoints/*' '*/latest.pt'
cd "$OCRAP_REPO"

  30) echo "停止；不要运行任何后续实验。"; exit 30 ;;

esac

6. 输出目录说明
============================================================

每个regime/variant都会生成：
  reports/<variant>_<regime>_paired.json
  reports/<variant>_<regime>_paired.csv
  reports/<variant>_<regime>_paired.wide.csv

导师展示表：
  reports/display/safe_progress_comparison.csv
  reports/display/safe_progress_comparison.md
  reports/display/safe_progress_comparison_full.csv
  reports/display/near_progress_comparison.csv
  reports/display/near_progress_comparison.md

  reports/display/contact_progress_comparison.csv
  reports/display/contact_progress_comparison.md
  reports/display/contact_progress_comparison_full.csv
  reports/display/ALL_REGIMES_REPORT_INDEX.json

视频与审计：
  videos/<variant>/<regime>/critical_scene_selection.json
  videos/<variant>/<regime>/rendered/VIDEO_INDEX.json
  videos/<variant>/<regime>/rendered/VIDEO_INDEX.csv
  videos/<variant>/<regime>/rendered/*.mp4（无ffmpeg时为GIF）

解释纪律：
  1. RC=30下任何结果都不用于算法优劣分析。
  2. RC=20后的closed-loop/baseline/video只用于探索性进度展示。
  3. 所有数值对比必须来自同一target-key集合；不得直接拼接上传的旧baseline汇总数字。
  4. 视频必须同时展示自动选择的positive toy examples和failure cases。
