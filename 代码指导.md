# OC-RAP 代码对齐修改指导（基于现有 ReCAP 代码库）

## 0. 结论

**不要从零重写。** 当前 ReCAP 代码库已经有可保留的工程骨架：root collection、MetaDrive/ScenarioNet 适配、BEV raster、action lattice/projection、root-shared mode seeds、teacher rollout、sharded dataset writer、训练/eval 脚本、基础测试。  
但当前代码只对齐旧论文中的 CARE/MERO 原型，不完全对齐当前论文 Method/Appendix 中的 **OC-RAP = Observation-Consistent Recovery Affordance Planning**。因此应采用：

> **在现有代码库上做一次“结构化语义重构”，不是小修小补，也不是完全重写。**

重构目标是把现有 `CARE + MERO + selector` 改成：

```text
prefix proposals
→ executable recovery affordance tokens
→ ReCoT root-shared counterfactual evidence
→ OC-MERO observation-consistent existential operator
→ CRISP calibrated selector
```

下面的指导是给代码生成大模型用的。要求它按模块完整实现，不要只改名字或保留旧语义。

## 1. 先修正论文中会影响代码实现的理论定义

在动代码前，必须确认论文 Method/Appendix 的以下定义。否则代码会实现出互相矛盾的版本。

### 1.1 `G_{a,j}^{m,*}` 不能写成三种恢复规格的 `min`

当前 Method 写法类似：

```tex
G_{a,j}^{m,\star}=\min\{G_{\mathrm{no}},G_{\mathrm{mr}},G_{\mathrm{post}}\}_{a,j}^{m,\star}.
```

但 Appendix 又说 reported teacher margin 是 **largest specification margin available to the witness**。这两者矛盾。

如果用 `min{G_no, G_mr, G_post}`，一个 no-contact witness 会被不相关的 post-contact 规格拖成失败；一个 post-contact stabilize witness 也会被 no-contact 规格误杀。

必须改成：

```tex
G_{a,j}^{m,\star}
=
\max_{s\in\{\mathrm{no},\mathrm{mr},\mathrm{post}\}}
G_{s,a,j}^{m,\star}.
```

并存储：

```python
spec_margin_star: [B,K,L,M,3]  # no, mr, post
spec_id_star:     [B,K,L,M]    # argmax over spec
margin_option:    [B,K,L,M]    # max over specs
Y_option:         [B,K,L,M]    # margin_option >= 0
```

### 1.2 μ-weighted existential operator 与 `c_R` 不能双重归一化

论文 OC-MERO 写法是：

```tex
pi_a^m = sigmoid(
  tau_R log sum_j mu(w_j | beta_a^m, a) exp(v_{a,j}^m/tau_R) - c_R
)
```

如果 `mu` 是概率分布，`sum_j mu_j = 1`，则当所有 option score 相同时：

```text
tau log sum_j mu_j exp(v/tau) = v
```

因此不需要再减 `tau log L`。若继续使用 `c_R = tau_R log L`，会把所有多 option prefix 系统性压低。代码应采用：

```python
log_mu = log(masked_softmax(mu_logits, dim=2))
pi = sigmoid(tau_R * logsumexp(log_mu + v / tau_R, dim=2) - c_R)
c_R = 0.0  # 默认
```

如果选择保留当前代码的“未加权 normalized logsumexp”，那就不是真正的 observation-consistent witness policy。建议实现 μ-weighted 版本。

### 1.3 Observation-consistency 是当前代码缺失的核心贡献，不是可选项

当前代码没有 posterior/beta、obs-equivalence class、class-level witness。必须新增：

```python
obs_class:       [B,K,M]        # post-prefix observation equivalence class id
obs_equiv:       [B,K,M,M]      # bool, equivalent post-prefix observation
beta_star:       [B,K,M,M]      # teacher posterior over root modes
witness_class:   [B,K,num_classes] or padded [B,K,M]
witness_oc:      [B,K,M]        # class-consistent witness for each mode
Y_oc:            [B,K,M]        # Y_option[b,k,witness_oc,m]
R_star:          [B,K]          # LCVaR(Y_oc, mode_probs)
```

旧代码的：

```python
Y_action = Y.max(axis=1)
R_star = LCVaR(Y_action)
witness = best option per mode
```

是 oracle-existential，允许每个 latent future 选择不同 witness，会产生 oracle leakage。必须替换。

### 1.4 CRISP 的校准变量必须补全

论文 selector 的 admissible set 包括：

```text
R_a - q_R >= eta_R
H_a + q_H <= eta_H
DeltaH_a + q_delta <= epsilon_H
C_a + q_C <= 0
```

当前代码只有 `q_R` 和 `q_H`，而且 `q_H` 实际用于 `dH`。需要明确区分：

```python
q_R:     recovery lower-tail offset
q_H:     absolute harm offset
q_delta: relative harm-gap offset
q_C:     rule violation / hard-shell violation offset
```

并在 calibration、selector、metrics 中同步。

### 1.5 旧 `P/G/C` 证据头必须改成 signed margin vector，不能继续作为主方法语义

当前代码中的主证据是 `P_star/G_star/C_star/U_star/H_star/K_star`，其中 `P/G/C` 分别近似碰撞概率、目标返回、控制/约束可行性等旧版 CARE/MERO 语义。当前论文的主方法不应再把这些旧标量作为 OC-MERO 的核心输入；否则 ReCoT 学到的是旧版证据分解，而不是恢复规格的 signed margins。

主方法必须改成：

```python
g_star:      [B,K,L,M,G_DIM]   # signed recovery-specification margins, positive is good
y_star:      [B,K,L,M]         # 1[margin_option >= 0]
h_star:      [B,K,M]           # first-contact / closest-approach harm
k_star:      [B,K,L,M]         # post-contact recovery deficit
u_star:      [B,K,L,M] or [B,K,M]
c_rule_star: [B,K,M] or [B,K]  # non-slacked rule violation for CRISP
```

OC-MERO 的 monotone calibrator 输入应为：

```python
concat(g_hat, -h_hat, -k_hat, -u_hat)
```

其中 `g_hat` 的每个分量都是“越大越安全/越可恢复”的 signed margin；harm、post-contact deficit 和 uncertainty 取负后进入单调网络，确保增加损害、恢复缺口或不确定性不会提高 recoverability。旧的 `P/G/C` 可以保留为 ablation 或 diagnostics，但不能作为主方法的训练目标、主模型输出或主实验指标。

## 8. OC-MERO implementation

新增 `recap/models/oc_mero.py`，或重写 `mero.py`。

### 8.1 Monotone calibrator

Current `MonoCalibrator` takes 5 features `[-P,G,C,-U,-K]`. Replace with:

```python
input = concat(
    g_hat,                         # all signed margins, positive is good
    -h_hat_expanded,
    -k_hat,
    -u_hat_expanded_or_tuple,
)
```

Use `PositiveLinear` or lattice network so all input dimensions are monotone nondecreasing. Since harm/deficit/uncertainty are negated, increasing harm cannot improve output.

### 8.2 μ-weighted existential operator

Implement:

```python
def masked_softmax(logits, mask, dim):
    logits = logits.masked_fill(~mask, -1e9)
    return torch.softmax(logits, dim=dim)

def existential_mu_aggregate(v, mu_logits, option_mask, tau_R=0.2, c_R=0.0):
    # v: [B,K,L,M]
    # mu_logits: [B,K,L,M]
    # option_mask: [B,K,L]
    mask = option_mask[..., None].expand_as(v)

    mu = masked_softmax(mu_logits, mask, dim=2)
    log_mu = torch.log(mu.clamp_min(1e-8))
    combined = log_mu + v / max(tau_R, 1e-8)
    lse = tau_R * torch.logsumexp(combined.masked_fill(~mask, -1e9), dim=2)
    pi = torch.sigmoid(lse - c_R)

    any_valid = option_mask.any(dim=2).unsqueeze(-1)
    return torch.where(any_valid, pi, torch.zeros_like(pi)), mu
```

Default:

```python
c_R = 0.0
```

### 8.3 Profiles

Return:

### 10.2 Function signature

```python
def select_action(
    actions,
    profiles: dict,
    U_drv: np.ndarray,
    q: dict,
    masks: dict,
    params: SelectorParams | dict | None = None,
) -> dict:
```

`q` must include:

```python
q_R, q_H, q_delta, q_C
```

### 10.3 Admissible set

```python
S_R = valid & (R - q_R >= eta_R)
S_H_abs = valid & (H + q_H <= eta_H)
S_H_gap = valid & (dH + q_delta <= epsilon_H)
S_C = valid & (C + q_C <= 0.0)

S = S_R & S_H_abs & S_H_gap & S_C
```

If `no_harm_constraint`, bypass both harm constraints.  
If `no_rule_constraint`, bypass `S_C`.

### 10.4 Decision

```python
a_nom = argmax U_drv over valid

if a_nom in S:
    status = "nominal_accepted"

elif S nonempty:
    score = U_drv - lambda_B*B - lambda_U*U - lambda_K*K_post
    choose argmax over S
    status = "calibrated_switch"

else:
    score = (
      lambda_R * relu(eta_R - R)
    + lambda_H * relu(dH - epsilon_H)
    + lambda_C * relu(C)
    + lambda_K * K_post
    )
    choose argmin over valid
    status = "minimum_risk"
```

Return selected witness and fallback controller id.
